# 웹 인수 조건과 시험 근거

대상: 소유자와 웹 인수 담당자. 마지막 검토: 2026-11-02.

제품 요구·정책·상위 설계는 웹 개발을 진행할 수 있는 상태다. 아래 표는 [요구사항 인수 시나리오](https://github.com/hanumoka/zm-docs/blob/main/docs/projects/zm-os/requirements.md#인수-시나리오)에 시험을 대응한다. 새 정책 정본이 아니며 실제 OAuth·수동 콘텐츠 검수·Android 검증을 자동 시험으로 대체하지 않는다. 측정 ref와 최종 실행 수치는 [작업 기록](../11-archive/2026-11.md)에 둔다.

## 추가 계약과 복구

공개 재시도의 중복 반영 방지, 불변 버전·worker lease 경합·실패 뒤 이전 판 보존은 기존 API 시험을 따른다. 이번 API 추가는 다른 앱 자격의 교환/조회와 긴급 중지 권한 소멸을 직접 확인한다. 저장 세대 시험은 삭제 전 실행의 늦은 요청과 dispose 후 transaction을 차단한다.

복구 도구는 정지한 독립 fixture의 DB dump·파일 지문을 같은 시점으로 묶고 별도 대상으로 복원한다. 승인된 이전 판으로 새 실행을 바꾸어도 기존 실행은 고정된 판을 유지한다. 응답 본문을 버린 공개 재시도도 검사하지만 실제 TCP 손실·운영 백업·암호키 복구·스키마 downgrade를 검증한 것은 아니다.

웹 완료 판정 전에 [실제 OAuth](web-oauth-local.md)를 실행하고 위 남은 범위와 수동 검수 기록을 확인한다. 자격 설정은 로컬 비추적 파일에만 두며 사용자에게 비밀 값을 대화로 전달하도록 요구하지 않는다.
