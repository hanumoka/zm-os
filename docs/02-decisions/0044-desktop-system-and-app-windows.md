# 데스크톱과 앱 창

대상: 소유자와 웹 구현·검증 담당자. 마지막 검토: 2026-11-03.

## 근거

소유자가 첫 화면을 기존 브라우저 OS로 유지하고 시스템 앱과 일반 인앱 모두 창으로 실행하도록 정정했다. 정책 정본은 zm-docs의 [DEC-0165](https://github.com/hanumoka/zm-docs/blob/main/docs/governance/decisions/DEC-0165-zm-os-desktop-and-windowed-system-apps.md)다. ADR-0042의 다중 창 제외만 변경하며 인증·검수·동의·격리 경계와 웹 우선 범위는 유지한다.

## 구현 결정

1. React/Vite 신규 호스트에서 데스크톱·시작 메뉴·작업표시줄을 제공한다. 첫 접속 시 Store를 자동으로 열지 않는다. Store·내 앱·계정·개발자·운영 화면은 시스템 앱 창이다.
2. 시스템 앱은 종류별 창 하나, 일반·검수 인앱은 실행 세션별 창으로 구분한다. 서버는 이미 여러 실행 세션을 지원하므로 스키마와 API 계약을 변경하지 않는다.
3. 창 상태는 reducer에서 위치·크기·표시 순서·최소화·최대화를 관리한다. React의 창 배열을 표시 순서로 재배열하지 않는다. iframe DOM을 옮겨 발생하는 새로고침을 방지한다.
4. 최소화·전환·크기 변경은 iframe과 MessagePort를 보존한다. 닫기는 해당 창을 제거하고 그 세션만 종료 요청한다. 종료 확인 실패는 안내하며 다른 창을 종료하지 않는다.
5. 최소화된 창도 실행 권한을 확인한다. 시스템 앱의 변경 후 모든 실행 창의 권한을 다시 확인한다. 로그아웃·계정 변경·이용 정지에서 이전 계정의 비공개 창을 정리하고 브리지를 해제한다. 실행 요청 뒤에도 현재 계정이 같은지 확인한 후 로컬 저장 브리지를 연결한다.
6. 넓은 웹 화면에서는 창을 이동·크기 변경·최소화·최대화한다. 제목 표시줄의 Alt+방향키와 크기 핸들의 방향키도 지원한다. 좁은 화면에서는 창이 작업표시줄 위 영역을 채우며 작업표시줄로 전환한다.
7. 시스템 앱은 호스트 권한의 내부 화면이며 번들 앱은 별도 origin과 sandbox를 유지한다. 앱은 호스트의 창 제어를 가리지 못한다. 비활성 인앱 위의 활성화 버튼은 iframe 내부 클릭이 호스트로 전파되지 않는 경우에도 창 선택을 제공한다.
8. 창 배치는 메모리에서만 유지한다. 새로고침 후 실행 자동 복구·다른 기기와 배치 동기화·Android 전용 동작은 이번 범위에 넣지 않는다.

## 시각 기준과 검증

기존 데스크톱의 하늘색·남보라 배경을 유지하고, 흰 창과 짙은 남색 작업표시줄로 실행 영역을 구분한다. 시스템 앱 아이콘은 같은 선 굵기의 SVG다. 기존 기능의 폼과 안내 문구를 창 안에 배치한다.

전제는 로컬 시험 PostgreSQL·Node.js 24·pnpm·Playwright다. `pnpm test:web-flows`는 기존 trial 데이터를 변경하지 않는 별도 DB·포트에서 실행한다. [데스크톱 시험](../../apps/platform-web/e2e/desktop.mjs)은 최초 화면·창 조작·실제 SDK의 동시 연결과 저장 격리·개별 종료·권한 철회·계정 변경·좁은 화면을 확인한다. 실패 시 해당 단계와 합성 결과를 기록하고 시험 소유 자원만 정리한다.

전체 웹 완료 판정은 실제 OAuth 보류 해제와 나머지 [완료 검증 목록](../01-architecture/web-completion-checklist.md)을 따른다. 창 구현을 공개 운영 준비 완료나 Android 검증으로 표시하지 않는다.
