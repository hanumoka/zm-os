## 2026-11-06 작업공간 환경 동기화와 창 배치 복원

구현 측정 ref는 `work/workspace-sync-20261106@6e5dfd5318c59d0180e4d614e42985864e53cf2c`이다. 이 측정은 작업 브랜치이며 기본 브랜치 반영 여부는 Git 이력으로 구분한다. 소유자가 선택한 범위를 [ADR-0049](../02-decisions/0049-workspace-sync-and-window-layouts.md)와 [사용·확인 절차](../01-architecture/workspace.md)에 기록했다.

배경·시스템 아이콘 위치를 계정별 PostgreSQL에 저장하고 다른 브라우저에서 이어 쓴다. 창 제목줄에서 좌우 정렬하고 작업공간 시스템 앱에서 배치를 저장·복원한다. 새로고침이나 환경 동기화가 앱을 자동 실행하지 않는다. 기존 창은 재사용해 입력을 유지하며 새 창에는 현재 권한으로 실행 세션을 발급한다. 창 배치는 앱 내부 내용 저장을 대신하지 않는다.

타입 검사·lint(오류 0, 기존 경고 27)·자동 시험 370개·빌드가 통과했다. 전체 독립 브라우저 확인 56개, PostgreSQL·파일 복구 통합 3개가 통과했다. 마지막 필드 갱신 보완 후에는 전체 자동 시험·타입·빌드와 작업공간 브라우저 8개를 재확인했다. 370개에는 기존 POC 251개와 Android 순수 로직 5개가 포함되며 Android 전용 검증을 재개하지 않았다.

API와 FE 시험은 최초 로컬 이전·서버 우선·다른 계정 분리, 순차 저장·수정 번호 충돌, 응답 소실과 새로고침 뒤 재시도, 늦은 응답·계정 전환·탈퇴 정리를 확인한다. 브라우저에서는 두 환경의 배경·아이콘 공유, 충돌 선택, 기존 메모 입력을 유지하는 반복 복원, 새 실행 세션, 중지·동의 철회 뒤 실행 거부, 390px 표시 조정과 서버 원본 유지도 확인했다. 복구 시험은 작업공간 JSON·수정 번호·마지막 저장 재시도 결과를 비교했다.

화면 자료는 Git 제외 `apps/platform-web/e2e-out/workspace-1793943244752/`에 있다. 설정·충돌 안내와 좌우 창 화면을 직접 검토했다. 합성 계정과 독립 시험 DB로 검증했으며 실제 다른 PC의 네트워크 접속·공개 운영·OAuth·추가 기본앱·파일 관리는 이번 확인 범위가 아니다.

기록 ref `d6f2d3232fb15c84e86e37b6df1c5f8dbba672ed`의 [CI 42169705621](https://github.com/hanumoka/zm-os/actions/runs/42169705621)는 일반 검사와 웹 56개 확인·artifact 저장·시험 DB 정지까지 성공했지만 마지막 setup-node 캐시 정리 단계에서 전체 실행이 취소됐다. 브라우저·Linux 의존성 설치 9분 40초와 웹 확인 2분 18초가 기존 웹 job 12분 제한을 소모했다. 검사 항목은 유지하고 웹 job 제한을 20분으로 늘려 정리까지 완료하도록 했다. 이 실행 자체를 전체 CI 성공으로 기록하지 않는다.

## 2026-11-06 기본앱·카테고리와 개인 작업공간

구현 측정 ref는 `work/app-types-20261106@7f008a541f31f51844be3743e08f3bfff5724341`이다. 이 측정은 작업 브랜치이며 기본 브랜치 반영 여부는 Git 이력으로 구분한다. [ADR-0048](../02-decisions/0048-default-apps-and-web-workspace.md)에 앱 제공 구분·운영 권한·계정별 숨김과 후속 작업공간 범위를 기록했다.

기본앱은 기존·신규 계정의 내 앱에 자동 표시하며 첫 실행 동의를 유지한다. 운영자 지정은 앱 ID·소유자·공개 버전·저장 데이터를 변경하지 않는다. Store·내 앱은 기본앱/개발자 앱과 기존 생산성·학습·도구·게임 카테고리를 조합하고, 사용자는 기본앱을 계정별로 숨기거나 다시 표시할 수 있다. 계정 삭제 worker는 숨김 선택도 제거한다.

타입 검사·lint(오류 0, 기존 경고 27)·자동 시험 359개·빌드가 통과했다. 독립 DB API 시험에서 신규 4개 시나리오를 추가하고 탈퇴 뒤 숨김 정리를 확인했다. 전체 독립 웹 확인 48개와 복구 통합 시험 3개가 통과했다. 359개에는 기존 POC 251개와 Android 순수 로직 5개가 포함되며 Android 기기 검증을 재개하지 않았다.

브라우저에서 운영자 지정·자동 목록·자동 동의 없음·카테고리 결합 필터·다른 브라우저의 숨김 반영·다른 계정 분리·복원 뒤 서버 메모 보존을 확인했다. 390px·1440px 화면을 검토했다. API 시험은 개발자의 기본앱 지위 위조와 권한 없는 변경, revision 충돌, 공개·중지 경계, 반복 마이그레이션도 확인했다.

환경 동기화·창 복원·계산기 등 추가 기본앱·파일 관리와 실제 OAuth·외부 메일·공개 운영은 이번 완료 범위가 아니다. 바탕화면 배경·아이콘 위치는 현재 브라우저에 남고 개인 메모·내 앱·숨김 선택은 플랫폼 DB에 남는다.

## 2026-11-06 Freedoom 게임의 Store 공개

구현 ref는 `work/doom-store-20261106@0096435318810122bba0b8a4fe01a478e781b298`이다. 이 측정은 작업 브랜치이며 기본 브랜치 반영 여부는 Git 이력으로 구분한다. [ADR-0047](../02-decisions/0047-wasm-freedoom-store-example.md)에 Wasm 실행 경계와 재배포 가능한 게임 예제를 기록했다.

Windows의 Node.js 24에서 타입 검사 15개 작업, lint 오류 0·기존 경고 27, 자동 시험 355개, 빌드 4개 작업, 독립 웹 흐름 확인 46개를 통과했다. 기존 39개에 게임 7개를 추가했으며 브라우저 오류는 없었다. 실제 렌더링·이동·발사 후 탄약 감소·정지·최소화/복원·소스 조회·390px 본문 표시를 확인했다. 시험 자산에서 JavaScript eval·Function·부모 DOM·외부 fetch가 계속 차단됨을 확인했다. Wasm만 허용하며 iframe의 allow-same-origin이나 새 외부 접속 허용을 추가하지 않았다.

별도로 사용 중인 로컬 시험 DB에서 일반 개발자 alice와 운영자 owner를 분리했다. 개발자 콘솔의 파일 선택·업로드·검수 요청, 운영자 화면의 검수용 실제 게임 실행·사유 있는 승인, 개발자의 ‘이 버전 공개’를 클릭했다. 일반 사용자 bob이 Store에서 동의·실행·이동·발사하는 것을 확인했다. ## 2026-11-03 OS 첫 화면과 다중 창

구현 ref는 `5c9c4740f201e2c9f4073bbbe521435711437e01`이다. 소유자가 기존 브라우저 OS를 첫 화면으로 유지하고 시스템 앱·일반 인앱 모두 창으로 실행하도록 정정했다. [ADR-0044](../02-decisions/0044-desktop-system-and-app-windows.md)에 결정·구현 경계를 기록했다. 기존 POC를 복사하지 않고 신규 플랫폼의 인증·검수·동의·실행 세션을 데스크톱 안에서 연결했다.

- 웹 최초 화면: 바탕화면·시스템 아이콘·시작 메뉴·작업표시줄. Store를 자동으로 열지 않는다.
- 시스템 앱은 종류별 창 하나, 일반·검수 앱은 실행 세션별 창이다. 창 이동·크기·최소화·최대화·전환을 지원한다. 제목 표시줄은 Alt+방향키, 크기 핸들은 방향키로도 조작한다.

- 다른 탭의 계정 변경과 로그아웃은 이전 계정의 모든 창과 브리지를 정리한다. 늦은 실행 응답은 현재 계정을 확인한 뒤 연결한다.
- 좁은 웹 화면은 창을 작업표시줄 위에 맞추며 실행 중인 창을 작업표시줄로 전환한다. 창 배치 영구 저장·새로고침 후 실행 복구는 제공하지 않는다.

### 검토에서 수정한 문제

- 개발자 승인 취소 후 공개 중단·종료 요청까지 막히던 권한 검사.

- 탈퇴 응답 유실 시 조회 자격을 잃는 문제. 링크를 탈퇴 전에 발급해 보관하도록 변경했다.
- 검수용 사용자·저장의 일반 실행 혼합. 동일 외부 앱의 검수/일반 식별자 두 개에 대한 탈퇴 삭제 요청도 회귀 시험에 포함했다.
- 모바일 WebView 이벤트의 `isTopFrame` 누락, 탐색 검사 무응답 시 허용, 로컬 HTTP 개발 연결 설정 누락.

주세션 자체 검토와 별도 설계 담당의 정적 재검토를 구분했다. 최종 독립 정적 검토는 추가로 확정한 중대 실패가 없다고 보고했다. 실제 기기·제공자·운영 환경의 검증 통과 판정은 아니다.

복원은 정지한 독립 fixture를 pg_dump하고 파일 지문과 함께 다른 DB/폴더로 복원한 시험이다. 손상·누락·덮어쓰기 거부, 실제 pg_restore 실패 정리와 새 대상 재시도, 승인 이전 판 공개, 같은 키 공개 재시도를 확인했다. 실제 TCP 응답 손실·운영 백업·키 복구·외부 앱 DB·브라우저 IDB 복원은 검증하지 않았다. Linux 결과는 원격 CI에서 따로 확인한다.

### 남은 범위

요구·기능·정책·상위 설계는 웹 구현을 진행할 수 있다. [인수 근거 대응표](../01-architecture/web-acceptance-evidence.md)에 정상·거부·수동 검수·미검증을 구분했다. 실제 Google/GitHub 설정은 제품 main·작업본의 환경 파일/trial 설정, Windows 환경변수, 관련 파일명 확인에서 찾지 못했다. 비밀 값은 출력하지 않았고 제공자 콘솔의 기존 앱 등록 여부는 확인하지 않았다.

[실제 웹 로그인 설정](../01-architecture/web-oauth-local.md)을 준비하고 실제 제공자 로그인·연결·해제·재인증, 두 유형 앱의 실제 계정 이용과 최종 수동 검수를 마친 뒤 웹 완료를 판정한다. 지금은 웹 전체 완료가 아니다. Android 추가 구현·전용 검증은 웹 완료 후이며 유료 인프라·일반 사용자 공개 운영은 별도다.

### 변경한 기능

- 첫 동의·검수 실행을 전송한 동안 취소·닫기·Escape를 차단하고 처리 중임을 안내한다. 취소한 뒤 늦게 앱이 뜨는 경합을 방지한다.
- 개발자 삭제 결과 선택에 현재 상태를 유지한다. 탈퇴 조회 실패 시 오래된 완료 결과를 제거하고 재시도하며 늦은 응답이 최신 화면을 덮지 않도록 한다.
- 삭제 상태에 실제 이용한 버전의 앱 이름을 표시한다. 등록 작업명·미이용 초안·개발자 메모는 공개하지 않고 `pending` 같은 이름도 번역하지 않는다.
- 운영자 검수 화면에 제외 기능과 확인 순서를 안내한다. 반려 후에도 개발자가 공개할 수 있다고 나오던 문구를 수정한다.
- 독립 DB·파일·포트의 웹 시험 실행기와 CI job을 추가한다. 기존 화면용 데이터는 초기화하지 않고 오류 원문·조회 자격을 공개 로그/artifact에서 제외한다.

### CI 재확인과 초기 빈 문서 이동 제거

문서 반영판 `6282770`의 [main CI 41438829256](https://github.com/hanumoka/zm-os/actions/runs/41438829256)에서 일반 검사는 성공했지만 검수 표본 브라우저 단계가 timeout으로 실패했다. 같은 판의 작업 브랜치에서도 외부 앱 진입 단계가 실패했다. 비밀 없는 단계·프레임 유무·알려진 종료 사유만 남기는 진단을 `f3aecf8`에 추가했고 [CI 41439609740](https://github.com/hanumoka/zm-os/actions/runs/41439609740)는 통과했다. Windows Edge의 검수 4회와 Chromium 전체 5회에서는 실패가 재현되지 않았다. 반복 성공을 원인 규명으로 간주하지 않는다.

실제 AppRunner·bridge를 사용하는 별도 회귀 fixture에서 StrictMode 초기 실행 40회와 실제 문서 이동 종료를 비교했다. 변경 전 `runner-lifecycle-1793620703454/result.json`은 초기 빈 문서 이동 41회·첫 문서 41회·다음 문서 1회, load 알림 83회였다. 변경 코드 `74fb3f544eeafc5b7e559f043c50d545c1b74c9a`는 JSX에서 최초 src를 설정하고 useLayoutEffect로 bridge를 설치하며 cleanup에서 src를 제거하지 않는다. 실제 unmount는 iframe DOM을 제거한다. 변경 후 `runner-lifecycle-1793620856682/result.json`은 빈 문서 이동 0회·첫 문서 41회·다음 문서 1회, load 42회였고 실제 다음 문서 이동은 정확히 한 번 종료됐다.

빈 문서 이동 0건을 명시 assertion으로 추가한 재실행도 통과했다. sandbox·CSP·메시지 source/origin/instance 검사·port 종료·저장 작업 중단·요청별 권한 확인은 유지하며 독립 설계 검토에서 추가 수정 요청이 없었다. 호스트 브리지 16개 회귀, FE 타입·lint·빌드와 외부 삭제/검수 13개 재실행도 통과했다. 최종 FE JavaScript는 323.27 kB, gzip 96.96 kB다.

이 회귀는 실제 FE와 합성 API 응답·앱 HTML의 시험으로, 실제 제공자·BE 권한 검증을 대체하지 않는다. **불필요한 빈 문서 이동은 재현·제거했지만 앞선 CI timeout이 그 경합 때문이라는 사실까지 확정하지는 않았다.** 재발 시 새 단계 기록과 실행 화면 회귀 결과로 좁혀 확인한다. React의 효과 재실행과 배치 시점은 [StrictMode](https://react.dev/reference/react/StrictMode)·[useLayoutEffect](https://react.dev/reference/react/useLayoutEffect) 공식 설명을 참고했다.

최종 코드 `74fb3f5`의 [CI 41441559034](https://github.com/hanumoka/zm-os/actions/runs/41441559034)는 두 job 모두 성공했다. Linux 자동 시험 331개·복구·빌드 및 Chromium 웹 13개와 실행 화면 회귀 2개를 통과했다. 원래 실패 기록과 재발 시 조사 항목은 삭제하지 않았다.
