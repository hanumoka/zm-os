# ADR-0048 — 기본앱과 개인 웹 작업공간

상태: accepted. 대상: 플랫폼·앱 개발자와 운영자. 검토일: 2026-11-06.

제품 정책은 [zm-docs DEC-0176](https://github.com/hanumoka/zm-docs/blob/main/docs/governance/decisions/DEC-0176-zm-os-default-apps-and-personal-web-workspace.md)다. zm-os는 로그인 사용자의 브라우저 작업공간이며 Store는 앱을 공급하는 시스템 기능이다. 이 구현은 기본앱 제공과 카테고리 표시를 구체화한다.

## 데이터와 권한

- 플랫폼 소유의 `apps.app_type`은 `default | developer`이며 기존 앱은 developer로 이행한다. 매니페스트는 이 필드를 받지 않는다. 카테고리는 승인된 버전의 기존 생산성·학습·도구·게임이다.
- 운영자만 사유·revision을 보내 지정·해제한다. 충돌은 409, 종료된 앱의 변경도 거부한다. 소유권·공개 판·이용자 식별자·동의·저장 데이터를 변경하지 않고 감사 이력을 남긴다.
- 내 앱은 명시적으로 추가한 앱과 공개된 기본앱을 합쳐 조회한다. 기본앱 자동 표시는 동의나 실행 세션을 생성하지 않는다. 공개 전·종료된 기본앱은 자동 표시하지 않고 중지된 앱은 실행 불가로 표시한다.
- 기본앱 제거는 계정별 `hidden_default_apps`에 숨김 선택을 저장한다. 다시 추가하면 숨김을 해제한다. 지정 해제·재지정에도 숨김 선택과 기존 데이터는 유지한다. 계정 삭제 worker는 숨김 선택도 삭제한다.
- 기존 메모장을 동일 앱 ID로 지정한다. 이름이 같은 다른 앱을 SQL migration으로 자동 지정하지 않는다. Freedoom과 나머지 앱은 개발자 앱을 유지한다.

## 화면

Store·내 앱은 기본앱과 개발자 앱을 나누고 검색·구분·카테고리를 조합한다. 상세는 제공 구분과 카테고리를 함께 표시한다. 개발자는 구분을 조회만 하며 운영 관리에서만 변경한다. 모든 기본앱에 기존 검수·공개·동의·격리·중지 규칙을 적용한다.

## 작업공간 후속 범위

계정별 배경·아이콘·바로가기 동기화, 창 정렬·배치 복원, 기본 도구 확장, 파일·문서 관리를 차례로 검토한다. 이번 구현에 환경 동기화나 새 기본앱을 포함하지 않는다. 계산기·시계·할 일 목록은 우선 후보이고 달력·북마크·마크다운 편집기·그림판도 후보로 남긴다. 창 배치 복원과 앱 내부 미저장 내용 복구는 별도 계약이다.

## 검증

독립 DB API 시험은 권한·위조 입력·revision 충돌·기존/신규 계정·동의 경계·필터 교집합·숨김·해제·중지·탈퇴 정리를 확인한다. 브라우저 시험은 운영 화면 지정, 사용자 목록, 숨김·다시 표시, 기존 서버 메모 보존과 좁은 화면을 확인한다. 실행 절차는 [로컬 시험](../01-architecture/platform-trial.md#기본앱과-카테고리-확인)을 따른다.
