# ADR-0049 — 계정별 작업공간 동기화와 창 배치 복원

상태: accepted. 대상: 웹·플랫폼 개발자. 검토일: 2026-11-06.

제품 요구는 [zm-docs DEC-0177](https://github.com/hanumoka/zm-docs/blob/main/docs/governance/decisions/DEC-0177-zm-os-synced-workspace-and-window-layouts.md)다. 환경 동기화·창 정렬·복원까지 우선 제공한다.

## 저장과 충돌

- `workspaces`는 계정마다 배경·아이콘·저장한 창 배치와 수정 번호를 보관한다. 앱 SDK의 개인 데이터 저장과 분리하며 인앱이 직접 접근하지 못한다.
- 최초 조회의 revision은 0이다. 쓰기는 현재 revision을 요구하고 DB 트랜잭션 안에서 확인·증가한다. 같은 마지막 requestId와 같은 내용의 재전송은 기존 결과를 반환한다. requestId를 다른 내용으로 쓰거나 다른 저장 뒤 오래된 번호로 요청하면 409다.
- GET·PUT은 expectedUserId와 현재 인증 주체를 비교한다. PUT은 기존 CSRF·계정 정지·재인증 검사도 적용한다. 유효 사용자 ID를 요청 본문에 넣었다고 그 계정에 접근할 수 없다.
- 서버에 자료가 없을 때만 같은 계정의 기존 로컬 배경·아이콘을 자동 이전한다. 서버 설정이 이미 있으면 그것을 사용한다. 기존 로컬 원본을 삭제하지 않는다.
- FE는 한 계정의 저장을 순서대로 보낸다. 저장 중 추가 변경, 늦은 응답, StrictMode 재연결, 로그아웃·계정 변경을 구분한다. 미저장 변경은 계정별 sessionStorage에 보관한다. 충돌 시 서버 설정 사용 또는 현재 설정 저장을 사용자가 선택한다.
- 다른 기기 변경은 포커스 복귀·연결 복구·보이는 화면의 15초 조회로 확인한다. 미저장 설정과 현재 실행 중인 창을 자동 교체하지 않는다.

## 창의 동작

좌우 정렬·최대화·최소화·드래그를 제공한다. 작은 화면에서는 가득 찬 창으로 표시하며 서버의 원래 배치를 임의 변경하지 않는다. 작업공간 앱에서 현재 배치를 명시적으로 저장하고 복원한다. 최대 24개이며 작업공간 설정 창·검수 미리보기는 저장 대상에서 제외한다.

저장하는 앱 식별자·표시 이름·위치·크기·정렬·최소화 상태는 실행 권한이 아니다. 앱 실행 URL·토큰·세션·초안은 계약에서 거부한다. 이미 실행 중인 같은 앱 창은 유효 세션을 확인해 재사용하고, 그 외에는 현재 권한으로 새 세션을 발급한다. 새 실행은 동의·공개·중지·계정 조건을 다시 검사한다. 실패한 창은 사유를 안내하며 나머지 창과 현재 작업을 유지한다.

## 삭제와 복구

탈퇴 worker는 해당 계정의 workspace 행을 삭제한다. 새 계정에는 이전 환경을 이어주지 않는다. 로컬 미저장 설정은 이전 계정 ID로 분리되어 새 계정에 적용되지 않는다. 독립 DB 백업·복원 시험은 환경 JSON·revision·마지막 요청 재시도 결과도 대조한다.

계약과 사용자 확인 절차는 [작업공간 안내](../01-architecture/workspace.md)를 따른다. 추가 기본앱·파일 관리·Android·공개 운영은 후속이다.
