# 웹 완료 검증 목록

대상: 소유자와 웹·BE·SDK 구현 담당자. 마지막 검토: 2026-11-02.

현재 단계는 웹·NestJS BE·worker·SDK·CLI와 두 유형 인앱의 로컬·시험 환경 구현·검증이다. [요구사항의 완료 기준](https://github.com/hanumoka/zm-docs/blob/main/docs/projects/zm-os/requirements.md#첫-개발-단계의-완료-조건)과 [웹 우선 결정](https://github.com/hanumoka/zm-docs/blob/main/docs/governance/decisions/DEC-0148-zm-os-complete-web-before-android.md)이 정본이다. Android 추가 구현·전용 검증은 웹 완료 후다. 이 목록은 정책을 새로 정하거나 기존 시험만으로 웹 완료를 선언하지 않는다.

## 기존 근거와 남은 확인

최신 추가 구현·시험 기준은 commit `3856a360d089bb1f252887f9ce7242c1a82b0773`다. 전체 자동 시험 331개와 외부 삭제·동의·검수 표본의 브라우저 13개 흐름을 통과했다. 이전 `402d592`의 브라우저 14개 흐름·복구 3개 시험과 `81c4979`의 브라우저·외부 API·탈퇴 근거는 각 ref의 기록으로 유지한다. 세부 조건은 [인수 근거 대응표](web-acceptance-evidence.md), 실행 결과와 한계는 [2026-11 기록](../11-archive/2026-11.md)에 둔다. **소유자는 실제 OAuth 작업을 일시 보류했다.** 실제 로그인은 미검증이며 모의 인증을 공개 운영 수단으로 바꾸는 결정은 아니다.

| 확인 범위 | 기존 근거 | 웹 완료 전 남은 확인 |
|---|---|---|
| 실제 Google·GitHub 로그인·계정 연결·해제·재인증 | API의 모의 인증·동시 해제·계정 분리 | 소유자 요청으로 보류. 재개 시 [등록·설정 안내](web-oauth-local.md)에 따라 실제 정상·거절·실패·연결·재인증 실행 |
| 앱 제작·등록·검수·공개·첫 동의·실행 | 웹 추가의 보완·반려·재제출, API 추가의 소유권·대리 변경·승인 후 미공개·재동의 | 실제 OAuth 이후 같은 흐름과 최종 수동 검수 |
| Store·내 앱·신고·계정 정지 | 웹 추가의 검색·분류·상세·독립 웹 세션 공유·신고 접수/처리, API의 독립 상태 시험 | Android 공유는 후속 |
| 앱 격리·로컬 저장·동의 철회·중지 | 웹 추가의 목록 밖 앱 관리·계정 변경 감지·여러 탭 늦은 저장 거부, 저장 migration/transaction 시험 | 다른 기기 물리 삭제는 제공 범위 아님 |
| 일반 API 앱과 외부 서버 책임 | 기존 외부 API 브라우저, API 추가의 다른 앱 교환·조회 거부·긴급 중지 권한 소멸 | 실제 웹 인증 이후 같은 앱 흐름. 이미 접수한 외부 업무 취소는 보장하지 않음 |
| 탈퇴·외부 삭제·조회 링크 | 외부 삭제 웹 8개 흐름: 접수→개발자 결과→조회, 대리 변경 거부, 실패·재시도·기존 상태 제거, 실제 이용 판 이름과 메모 비공개 | 실제 제공자 재인증. 외부 DB의 실제 삭제는 개발자 책임 |
| 첫 동의 취소·검수 내용 확인 | 화면 취소 후 앱별 식별자·실행·동의·코드·토큰 행 0개, 요청 지연 중 닫기 방지. 제외 기능 3개 표본 반려·개인 메모 표본 승인 | 운영 앱별 실제 내용 검수는 계속 필요. 표본은 자동 악성 행위 탐지를 증명하지 않음 |
| 실패 복구·시험 환경 운영 | 별도 DB/파일 복원 3개 시험·26개 테이블·8개 파일·두 버전·이전 승인 판 복귀 | 운영 백업·키 복구·schema downgrade는 후속 |
| 독립 개발 도구·두 예제·문서 | 기존 SDK·CLI·두 예제, 이번 회귀와 인수 대응표 | 실제 OAuth 및 수동 검수 근거를 합쳐 웹 완료 판정 |

## 진행 순서

전제: [로컬 시험 안내](platform-trial.md)의 Node.js·pnpm·Docker 환경과 시험 데이터를 사용한다. 실제 로그인에는 소유자의 Google·GitHub OAuth 앱 설정이 필요하다. 자격증명은 로컬 비추적 설정에 두고 대화·로그·커밋에 넣지 않는다.

1. 기존 시험과 요구사항을 대조해 위 표의 누락 근거를 확인한다. 코드·동작이 바뀌지 않은 통과 시험을 시험 횟수를 늘리기 위해 반복하지 않는다.
2. 소유자가 OAuth 작업을 재개하면 설정을 준비하고 제공자별 로그인·취소/거절·계정 연결·재인증을 실행한다. 현재는 보류 상태로 유지하고 독립적인 웹 확인을 진행한다.
3. 누락된 웹 흐름·시험 DB 복원·실패 경계의 근거를 보완한다. 확인된 결함을 수정하면 해당 동작과 필요한 회귀 검사를 실행한다.
4. 웹 완료 기준별 근거·남은 문제·측정 ref를 기록한다. 기준을 충족한 뒤 Android 전용 구현·검증 단계로 이동한다.

완료 확인: 실제 웹 OAuth와 두 유형 인앱, 사용자·개발자·운영자 흐름, 권한·격리·철회·탈퇴·실패 복구가 요구사항의 웹 조건을 충족하며 재현 기록이 있어야 한다. Android 미검증은 이 판정을 막지 않는다. 유료 인프라·일반 사용자 공개 운영은 이 완료 기준에 포함하지 않는다.

실패 대응: 실제 제공자 설정 문제는 오류 종류와 필요한 설정 위치만 기록하고 비밀 값을 출력하지 않는다. 재현 실패는 해당 조건을 미검증 또는 실패로 남기고, 원인을 수정한 뒤 영향을 받는 확인을 다시 수행한다. 다른 작업의 DB나 사용자 데이터를 초기화하지 않는다.
