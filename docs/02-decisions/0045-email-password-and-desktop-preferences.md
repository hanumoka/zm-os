# 이메일 인증과 바탕화면 설정

대상: 소유자와 웹 구현·검증 담당자. 마지막 검토: 2026-11-03.

## 근거

소유자는 이메일·비밀번호 가입을 추가하고 인증을 마친 뒤에만 이용하도록 선택했다. 제품 정책은 zm-docs의 [가입과 로그인 요구사항 및 연결된 결정](https://github.com/hanumoka/zm-docs/blob/main/docs/projects/zm-os/requirements.md#가입과-로그인)을 따른다. 이어 Windows·macOS를 참고한 바탕화면 기본 기능, 특히 아이콘 드래그를 요청했다. ADR-0044의 창 실행·세션 격리와 실제 OAuth·Android 보류는 유지한다.

## 이메일 인증 구현

1. 가입 요청에는 이메일·만 19세 이상 자가 확인을 받는다. 인증 링크에서 비밀번호를 정한 뒤 계정을 만든다. 주소만 아는 사람이 타인의 비밀번호를 먼저 정하는 흐름을 만들지 않는다. 인증 완료 후 자동 로그인하지 않는다.
2. 주소는 앞뒤 공백 제거·소문자로 비교한다. 공급자별 별칭 변환은 하지 않는다. 소셜 계정의 이메일과 자동 합병하지 않는다.
3. 비밀번호는 NFC 정규화 후 15~128개 Unicode 문자로 받는다. 공백·한글을 허용하고 반복 문자·일부 널리 쓰는 비밀번호를 거부한다. 전체 유출 비밀번호 데이터베이스 검사는 아니다. 무작위 16바이트 salt와 Node scrypt(N=131072,r=8,p=1,64바이트 결과)를 사용한다. 없는 계정도 같은 계산 비용으로 검증한다. [OWASP 저장 권고](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [NIST 비밀번호 요구](https://pages.nist.gov/800-63-4/sp800-63b.html)를 참고한 선택이며 표준 준수 인증을 주장하지 않는다.
4. 인증 링크는 15분·일회용이다. DB에는 해시·목적·대상·만료를 저장한다. 재발급·완료·비밀번호 변경·탈퇴 때 이전 증명을 제거한다. FE는 링크 fragment를 읽은 뒤 주소 표시줄에서 제거한다. 가입·재설정 요청 응답은 주소 존재 여부와 무관하게 같다. [OWASP 재설정 권고](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)
5. 15분 창에서 실제 소켓 IP별 100회, 경로별 주소 요청 5회·로그인 12회, 토큰별 완료 10회, 인증 세션별 변경·재인증 10회를 제한한다. 실패해도 별도 트랜잭션의 횟수는 남는다. 현재 loopback 시험 환경용이며 운영 프록시·분산 제한은 별도 검증 대상이다.
6. 현재 계정의 최근 재인증 후 이메일 연결을 요청하며 완료 때 같은 사용자·웹 세션을 확인한다. 다른 계정의 이메일을 가져오거나 기존 자격 정보를 덮어쓰지 않는다. 해제는 남길 수단으로 재인증하며 마지막 수단은 보호한다.
7. 변경은 현재 비밀번호, 재설정은 이메일 인증 증명을 요구한다. 성공 시 모든 웹 세션·앱 실행 권한·미완료 인증 증명을 철회한다. 검증 중 자격 정보가 바뀌면 세션을 발급하지 않는다. 정지 계정은 기존 제한 세션 정책을 따른다.
8. 탈퇴 즉시 비밀번호와 미완료 증명을 제거하고 worker도 잔여 삭제를 수행한다. 같은 이메일 재가입은 새 사용자다. 이메일은 본인의 계정 화면에만 제공하고 앱 SDK에는 전달하지 않는다.

## 로컬 메일 전달

현재 local-test 환경에서는 cfg.files의 mail 디렉터리로 발송을 대체한다. 외부 이메일은 보내지 않는다. `ZM_TEST_AUTH=1`일 때만 API 포트+2의 loopback 개발 메일함을 연다. 앱 API로 메일 목록을 제공하지 않는다. Host·Origin·브라우저 요청 종류 검사, frame 금지·no-store·no-referrer·HTML escaping을 적용한다. 링크 파일은 메일함 조회 시 만료된 항목을 정리한다. 프로세스가 꺼져 있거나 조회하지 않으면 로컬 파일은 남을 수 있으며 Git 추적에 넣지 않는다.

실제 메일 전송 adapter·발신 도메인·재시도·전달 결과·운영 환경의 개인정보 보관은 후속이다. `ZM_TEST_AUTH=0`에서는 메일함을 열지 않는다. 공개 서비스 인증 제공이 완료됐다는 뜻이 아니다.

## 바탕화면 구현

아이콘은 한 번 클릭해 선택하고 두 번 클릭·Enter로 연다. 드래그는 격자에 맞추며 점유된 칸에서는 두 아이콘을 교환한다. 방향키로 선택, Alt+방향키로 이동, Ctrl/Cmd+A로 전체 선택, Shift+F10으로 메뉴를 연다. 우클릭 메뉴에서 앱 열기·이름 정렬·배치 초기화·모든 창 최소화·세 배경을 제공한다.

아이콘 배치·배경은 `zm-os:desktop:v1:<userId>` 브라우저 저장소로 분리하고 방문자는 guest를 쓴다. 잘못된 설정은 기본값으로 복원하며 저장 실패를 안내한다. 작은 화면에서는 보이는 영역에 다시 배치하고 원래 저장 값은 유지한다. 창 배치·실행 세션은 메모리에서만 관리하며 자동 실행 복원·기기 간 동기화는 제공하지 않는다.

## 검증과 실패 대응

전제는 Node.js 24·pnpm·trial PostgreSQL·Playwright다. `pnpm test`와 `pnpm test:web-flows`를 실행한다. 이메일 API 시험은 독립 DB에서 링크·암호·연결·철회·탈퇴·요청 제한을, 브라우저 시험은 가입→메일함→확인→로그인→변경·재설정과 아이콘 입력·저장·계정 분리를 확인한다. 실패 시 합성 결과의 단계만 기록하며 토큰·비밀번호를 로그나 산출물에 출력하지 않는다. 시험에서 만든 서버·DB·임시 파일만 정리한다.
