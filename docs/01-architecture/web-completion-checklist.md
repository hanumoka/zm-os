# 웹 완료 검증 목록

대상: 소유자와 웹·BE·SDK 구현 담당자. 마지막 검토: 2026-11-02.

현재 단계는 웹·NestJS BE·worker·SDK·CLI와 두 유형 인앱의 로컬·시험 환경 구현·검증이다. [요구사항의 완료 기준](https://github.com/hanumoka/zm-docs/blob/main/docs/projects/zm-os/requirements.md#첫-개발-단계의-완료-조건)과 [웹 우선 결정](https://github.com/hanumoka/zm-docs/blob/main/docs/governance/decisions/DEC-0148-zm-os-complete-web-before-android.md)이 정본이다. Android 추가 구현·전용 검증은 웹 완료 후다. 이 목록은 정책을 새로 정하거나 기존 시험만으로 웹 완료를 선언하지 않는다.

## 기존 근거와 남은 확인

기존 시험 근거는 구현 commit `81c4979c71967aa387be18839d51219b9447b590`의 [2026-11 기록](../11-archive/2026-11.md)이다. 아래의 기존 시험은 2026-11-01 로컬 실행 및 해당 commit의 CI 결과다. 이번 문서 작성에서 새 기능 시험을 실행하지 않았다. 관련 시험이 있다는 사실과 요구사항의 모든 인수 조건을 충족했다는 판정은 구분한다.

## 진행 순서

전제: [로컬 시험 안내](platform-trial.md)의 Node.js·pnpm·Docker 환경과 시험 데이터를 사용한다. 실제 로그인에는 소유자의 Google·GitHub OAuth 앱 설정이 필요하다. 자격증명은 로컬 비추적 설정에 두고 대화·로그·커밋에 넣지 않는다.

1. 기존 시험과 요구사항을 대조해 위 표의 누락 근거를 확인한다. 코드·동작이 바뀌지 않은 통과 시험을 시험 횟수를 늘리기 위해 반복하지 않는다.
2. 실제 웹 OAuth 설정이 준비되면 제공자별 로그인·취소/거절·계정 연결·재인증을 실행하고 결과를 기록한다. 설정이 없으면 이 항목은 대기로 남기고 독립적인 웹 확인을 진행한다.
3. 누락된 웹 흐름·시험 DB 복원·실패 경계의 근거를 보완한다. 확인된 결함을 수정하면 해당 동작과 필요한 회귀 검사를 실행한다.
4. 웹 완료 기준별 근거·남은 문제·측정 ref를 기록한다. 기준을 충족한 뒤 Android 전용 구현·검증 단계로 이동한다.

완료 확인: 실제 웹 OAuth와 두 유형 인앱, 사용자·개발자·운영자 흐름, 권한·격리·철회·탈퇴·실패 복구가 요구사항의 웹 조건을 충족하며 재현 기록이 있어야 한다. Android 미검증은 이 판정을 막지 않는다. 유료 인프라·일반 사용자 공개 운영은 이 완료 기준에 포함하지 않는다.

실패 대응: 실제 제공자 설정 문제는 오류 종류와 필요한 설정 위치만 기록하고 비밀 값을 출력하지 않는다. 재현 실패는 해당 조건을 미검증 또는 실패로 남기고, 원인을 수정한 뒤 영향을 받는 확인을 다시 수행한다. 다른 작업의 DB나 사용자 데이터를 초기화하지 않는다.
